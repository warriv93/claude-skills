# Phase 1 — Plan the active milestone

1. **Pick the milestone:**
   - A new feature: file it under the epic whose theme it extends, or start a new epic when none fits, and say in one line where it went. No `podium.json` yet → write one with `project` (`title`, `summary`), that epic (`id` as a slug, `title`, one-line `summary`), `needsYou: null` and `dispatcher`. Add a milestone (next free id) of the feature's title, `status: "working"`, `phase: "recon"`, empty `stories` and `artifacts`, and point `active` at it. Start the Podium (SKILL.md, Podium) and give the user the link.
   - `REQUEST plan <id>`, or `/orchestrate-deep-plans <id>`: another milestone is `working` → append a `request` event saying `<id>` waits for it, and tell the user. A `REQUEST plan` for a `parked` or `dropped` milestone → it stays put until the user confirms (naming it in `/orchestrate-deep-plans <id>` is that confirmation): set `needsYou: {reason: "<id> was <status>: <its note's reason>. Unpark and plan it?"}`, append a `request` event, and ask in `AskUserQuestion` when available; while unavailable it waits for `HUMAN available` (unparking is never an assumption). Otherwise set `active` to it, its `status: "working"`, `phase: "recon"`, and append a `planned` event.
2. **Run `/deep-plan`** for the active milestone: its brief when one exists (a `draft` brief → grill its `open` questions first), otherwise the feature description. deep-plan sees `podium.json`, keeps the milestone's `phase`, `artifacts` and the epic's `needsYou` current at every checkpoint and gate, and returns here after its Phase 2 checkpoint. When deep-plan asks for a context reset, the user re-invokes `/orchestrate-deep-plans`, and this phase resumes inside deep-plan from the ledger.
3. Set the milestone's `branch` to the feature branch speckit created, and its `spec` to the speckit folder.

Done when the ledger names Phase 3, the milestone's `spec.md` and `tasks.md` are on disk, and its `branch` is set.
